# AI Agents — How They're Actually Built

> **A learning project.** This repo exists to build understanding, not to be a
> library or a product — don't depend on it. The code and the notes were
> generated by Claude (Opus 5) in conversation with me, then read and run;
> every `example.py` was executed end-to-end against the real Anthropic API,
> and the outputs quoted in the READMEs are from those runs.

The goal of this repo: build a working mental model of how modern AI agents work, so that
when a company says *"we build AI agents for patents / insurance / payments / coding / support"*,
you can reason at a high level about what's probably happening inside their product.

## The one-sentence mental model

> **Every "AI agent" product is roughly: an LLM in a loop, with tools, grounded in domain
> data, wrapped in reliability engineering.**

That sentence is the whole repo. Each module builds one piece of it, and the case studies
map real product categories back onto it.

```
                        ┌───────────────────────────────────────┐
                        │   RELIABILITY  (evals, guardrails,    │
                        │   tracing, human-in-the-loop)         │
                        │  ┌─────────────────────────────────┐  │
   domain data ────────▶│  │        THE AGENT LOOP           │  │
   (RAG, memory,        │  │                                 │  │
    documents)          │  │   LLM ──▶ tool call ──▶ result  │  │
                        │  │    ▲                       │    │  │
                        │  │    └───────────────────────┘    │  │
                        │  │      repeat until task done     │  │
                        │  └─────────────────────────────────┘  │
                        └───────────────────────────────────────┘
```

## Modules

Work through these in order. Each is a `README.md` (the concept, and where it shows up in
real products) plus a small runnable `example.py`. Modules 00–08 use the raw Anthropic API
on purpose — no frameworks — so the mechanics stay visible. Frameworks appear in module 09.

| # | Module | The piece it builds |
|---|--------|---------------------|
| 00 | [LLM API foundations](modules/00-llm-api-foundations/) | What one LLM call actually is: messages, tokens, context, statelessness |
| 01 | [Tool use](modules/01-tool-use/) | Function calling — **the** core agent primitive |
| 02 | [The agent loop](modules/02-the-agent-loop/) | An agent from scratch in ~120 lines: it's just a loop |
| 03 | [Structured output](modules/03-structured-output/) | JSON schemas & extraction — the heart of document-heavy verticals |
| 04 | [RAG & embeddings](modules/04-rag-and-embeddings/) | Grounding the agent in domain data |
| 05 | [Memory & context](modules/05-memory-and-context/) | History management, summarization, long-term memory |
| 06 | [Orchestration](modules/06-orchestration/) | Workflows vs agents, subagents, multi-agent, durable execution |
| 07 | [MCP](modules/07-mcp/) | The standard protocol for connecting agents to tools |
| 08 | [Reliability](modules/08-reliability/) | Evals, tracing, guardrails, human-in-the-loop |
| 09 | [Frameworks landscape](modules/09-frameworks-landscape/) | LangGraph, Agents SDKs, CrewAI — when companies use them vs raw APIs |
| 10 | [Production concerns](modules/10-production-concerns/) | Cost, latency, caching, prompt injection, deployment |

## Case studies (the payoff)

Five archetypes, chosen so that together they cover nearly every "AI agents for X" company:

- **Coding agent** (Claude Code / Cursor style) — the deepest agent loop in production
- **Deep research agent** — multi-agent orchestration and long-horizon planning
- **Computer-use agent** — vision, action spaces, the novel frontier
- **Support agent** (Sierra / Fin style) — the reliability-engineering masterclass
- **Document-workflow agent** — the enterprise archetype (patents, insurance, payments are all variants of this)

## Setup

```bash
# 1. Install deps (uses uv — https://docs.astral.sh/uv/)
uv sync

# 2. Set your API key
cp .env.example .env       # then paste your key from https://platform.claude.com/

# 3. Run any module's example from the repo root
uv run modules/00-llm-api-foundations/example.py
```

Examples use the Anthropic API with `claude-opus-5`. Each run costs a fraction of a cent
to a few cents.
